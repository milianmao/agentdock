# 测试策略

规模：788 个 Go 文件里 302 个是 `*_test.go`，其中 288 个文件定义了 **1426** 个顶层 `Test*` 函数，覆盖 62 个目录。`func Benchmark` **0 个** —— 本项目不测吞吐，只测行为。

## 1. 分层

| 层 | 形态 | 数量 | 运行位置 |
|---|---|---|---|
| Go 单元测试 | `internal/**/*_test.go` | 1426 个函数 | 每个 PR，三平台 |
| 脚本策略测试 | `scripts/test/*_test.go` | ~20 个 | Linux CI + 本地 `make test-scripts` |
| Shell/PowerShell E2E | `scripts/test/*.sh`、`*.ps1` | ~30 个 | 按平台触发 |
| 浏览器集成 | `-tags browser_integration` | 独立 job | 单独 job（xvfb） |
| 容器测试 | `scripts/test/test-docker-images.sh` | — | 单独 job |
| 手工/VM E2E | `linux-installer-e2e-vps.sh` 等 | — | 不自动跑 |

**无 mock 框架**。测试用真实临时目录、真实文件、真实子进程。`internal/plugin` 的测试会真的走 stage → activate → finalize 全流程 + 模拟崩溃（`plugin_test.go:21-31` 直接操作 `manager.pending` 模拟中途崩溃）。

## 2. 三平台矩阵

`ci.yml:16` 的 `go` job：`os: [ubuntu-latest, macos-latest, windows-latest]`。

| 步骤 | Linux | macOS | Windows |
|---|---|---|---|
| `gofmt` 检查 | ✅ | — | — |
| `go test ./... -count=1 -timeout=3m` | ✅ | ✅ | ✅ |
| ACP 竞态 `-count=20` | ✅ | — | — |
| `go test -race ./... -count=1 -timeout=3m` | ✅ | — | — |
| `go vet` | ✅ | — | — |
| `go build` | ✅ | — | — |
| `make test-scripts` | ✅ | — | — |
| `make test-scripts-macos` | — | ✅ | — |
| DPAPI round-trip | — | — | ✅ |
| 未跟踪文件洁净检查 | — | — | ✅ |

`continue-on-error` 未使用，`fail-fast: false` 让三平台结果都能看到。

**`-count=1` 是强制的**：禁用 Go 的测试结果缓存。CI 有断言守住这条（`ci_workflow_test.go:49-69`）。

**Windows 的洁净检查**（`git ls-files --others --exclude-standard`）是硬要求：任何测试留下未跟踪文件就失败（陷阱 C2）。

## 3. 竞态测试

### ACP steering

```bash
go test -race ./internal/acp \
  -run 'Test(StartPromptWaitsForPromptDispatchBeforeSteering|ClaudeSteeringFallbackCancelsOldRunAndStartsObservableTurn|CodexSteeringFallbackCancelsOldRunAndStartsObservableTurn)$' \
  -count=20
```

`-count=20` 因为该竞态是时序相关的，单次通过不代表安全。改 `prompts.go` / `prompt_settle.go` / `compatibility.go` **必跑**（陷阱 G1）。

`-timeout=90s` 上限，`ci_workflow_test.go` 断言这些字符串存在 —— 删掉或改参数会让 CI 自检失败。

### 全仓 race

`go test -race ./... -count=1 -timeout=3m` 只跑 Linux，因为 race detector 需要 cgo，macOS/Windows 上代价过高。

## 4. 定制 build tag

| tag | 用途 | 覆盖 |
|---|---|---|
| `browser_integration` | 真实 Chromium 集成 | `./internal/tool/browser`、`./internal/app` |

```bash
go test -race -tags browser_integration ./internal/tool/browser ./internal/app -count=1 -timeout=3m
```

需要 xvfb（`ci.yml:112` 的 `browser-integration` job）。默认构建不含，所以本地 `go test ./...` 不会拉 Chromium。

## 5. 脚本测试

### `make test-scripts`

```
./scripts/test/check-scripts.sh
go test ./scripts/test -run TestScriptGovernance -count=1
```

`check-scripts.sh` 做的事：
1. `python3 ./scripts/test/test_shell_variable_boundaries.py` —— 检查 shell 变量边界
2. 若有 `shellcheck` 则跑，没有则跳过（**不是硬依赖**）

`--macos` 变体：只检查 zsh 脚本 + 跑 `test-install-macos.sh` 与 `test-macos-app.sh`，且要求 `uname -s == Darwin`。

### 治理清单的双向校验

见 [编码规范](./编码规范.md#6-脚本治理) —— 新增任何 `scripts/`、`packaging/` 下的脚本而不登记清单会直接失败。

### Windows PowerShell 测试

15 个 `.ps1` 覆盖安装器、隧道、云组件、运行时注册、旧版迁移、标准用户安装等。它们由 `windows-installer.yml` 的 `validate` job 驱动，`timeout-minutes: 30`。

`windows-installer.yml` 有 **always-present PR gate**：`changes` job 用 `git diff --name-only` 判定相关路径，`validate` 按需跑，`gate` job 用 `if: always()` 汇总 —— 即使跳过也要有明确结果，不能出现"没有状态"的 PR 检查。

## 6. 什么必须补永久测试

按此仓的实际做法归纳：

| 改动 | 是否补测试 | 理由 |
|---|---|---|
| 状态机新增转移（如 `taskstate` 的 checkpoint 语义） | **必须** | 消费者可见；边界多 |
| 事务/回滚路径（`plugin` activation、`updateengine` arbiter） | **必须** | 失败代价高，无法手工覆盖 |
| 路径解析与越界（`workspace`、`package` 解压） | **必须** | 安全边界 |
| 并发原语（租约、锁、`Close` 顺序） | **必须**，且最好带 `-race` | 竞态难以复现 |
| 线上策略断言（CI 约束、日志策略、脚本治理） | **必须**放在 `scripts/test/` | 防止"顺手改掉" |
| 新增工具的动作分发 | **建议** | 参数校验失败模式值得固定 |
| wiring / 转发 / mock 回声 | **禁止** | 见下文 |
| 一次性的验证脚本 | 用完即删 | 不进仓库 |

### 明确不测的东西

以下模式在仓内几乎看不到（符合工程惯例）：

- 纯 `struct` 字段赋值往返
- `errors.Is` 之类标准库行为
- 只断言"不 panic"或"err == nil"
- 断言源码文本（例外：`ci_workflow_test.go` 与 `script_governance_test.go` **故意**断言 YAML/清单内容，因为这些**本就是要锁死的契约**）

`scripts/test/*_test.go` 里的文本断言是**策略测试**，不是"测源码"——它们锁的是 CI 配置、日志策略、脚本治理这类需要防回归的元契约。

## 7. 本地验证节奏

```bash
# 改完 Go 代码
make fmt && make test

# 改了脚本/CI
make test-scripts

# 改了并发相关
make race

# 提交前
make check
```

单包迭代：`go test ./internal/plugin -run TestManagerLifecycle -v`。

**不跑全量 race 是常见疏漏**：`-race` 不在 `make check` 里，`Runtime.Close` / 锁顺序类改动必须单独跑。

## 8. 测试数据

`scripts/test/testdata/fake-cloudflared/main.go` 是**被跟踪的**测试替身 Go 程序 —— 用来在 CI 里验证 cloudflared 组件的下载、校验、安装、健康检查全链路，不依赖真实上游。

`internal/component/catalog-v1.json` 的 pin 值也被 CI 校验：`windows-installer.yml` 断言 `cloudflared` 的 SHA-256 与 catalog 一致，且**禁止**从 `cloudflared/releases/latest` 下载。
