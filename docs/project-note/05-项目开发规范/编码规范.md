# 编码规范

规范由三层约束共同构成：**工具强制**（`Makefile` 目标 + CI）、**静态检查**（`scripts/test/*_test.go`）、**约定**（本文明示）。凡有工具强制的，本文只指出位置，不复述内容。

## 1. 强制门禁

`make check` 是提交前的最小集合（`Makefile:44`）：

```make
check: fmt-check test test-scripts vet build
```

| 目标 | 命令 | 作用 |
|---|---|---|
| `fmt` | `gofmt -w ./cmd ./internal ./desktop` | 格式化 |
| `fmt-check` | `gofmt -l` 非空即失败 | CI 门禁 |
| `test` | `go test ./...` | 单测 |
| `test-scripts` | `./scripts/test/check-scripts.sh` + `TestScriptGovernance` | 脚本语法 + 治理清单 |
| `vet` | `go vet ./...` | 静态分析 |
| `race` | `go test -race ./...` | 竞态（CI 单独跑，不在 `check` 里） |
| `build` | `go build -trimpath -ldflags ...` | 编译 |

CI 的格式化检查与 `make fmt-check` 不完全一致：CI 走 `git ls-files '*.go' | gofmt -l`（`ci.yml`），覆盖 `tools/`、`scripts/`，比 Makefile 的目录枚举更全。**以 CI 为准**。

## 2. 包布局

### 顶层划分

| 目录 | 职责 | 不允许出现 |
|---|---|---|
| `cmd/<binary>` | 进程入口、参数解析、子命令分派 | 业务逻辑 |
| `internal/<domain>` | 领域实现 | 跨领域直接 import 对方的内部类型 |
| `internal/tool/<domain>` | 单个工具族（13 个子包） | 直接持有 `*app.Runtime` |
| `desktop/` | 平台原生 UI | 被 Go 代码 import |
| `packaging/` | 打包脚本与资源 | 运行时逻辑 |
| `scripts/` | 安装/测试/治理脚本 | 产品能力（见 §6） |
| `tools/release` | 发布辅助 Go 程序 | 被主模块 import |

`internal/` 有 39 个包，单包职责边界靠**名字**表达，不做额外分层目录。

### 文件命名

| 后缀 | 含义 | 例 |
|---|---|---|
| `_windows.go` / `_darwin.go` / `_linux.go` | 编译期平台选择 | `swap_darwin.go` |
| `_other.go` | 除上述之外的平台 | `updateplatform/other.go` |
| `_test.go` | — | 全包 |
| `contract.go` | 常量、枚举、schema、请求/响应结构 | `tool/mcp/contract.go`、`evolution/contract.go` |
| `service.go` | 业务实现 | `tool/plugin/service.go` |
| `store.go` | 持久化 | `plugin/store.go`、`taskstate/store.go` |
| `types.go` | 纯类型定义（无逻辑） | `plugin/types.go`、`mcp/client/types.go` |
| `manager.go` | 生命周期管理 | `mcp/client/manager.go` |
| `model.go` | 领域模型 + 校验 | `taskstate/model.go` |
| `apply*.go` / `activate*` | 平台动作 | `installer/apply.go` |

**`contract.go` 是一个真实约定**：它让"这个领域对外承诺了什么"能在一次文件打开内读完，而不必翻 service 实现。

### 反面示例

`internal/mcp/registry.go` 只有一行类型别名，`internal/mcp/schema.go` 是空文件 —— 都不是注册表/校验器。不要按名字猜（陷阱 E4）。

## 3. 错误处理

### 三条规则

1. **边界归一**：工具层一律返回 `*toolcore.ToolError`。`mcp/client.Error`、`acp.Error` 在各自 `tool/*` 包的入口处转换，不向上泄漏。
2. **包装用 `%w`**：内部错误链用 `fmt.Errorf("...: %w", err)` 保留因果（全仓 1038 处）。`errors.Join` 用于多路清理（102 处，典型是 `Runtime.Close`）。
3. **错误信息不含敏感数据**：Nexus 的 `resource-library` 失败只记 `error_code` + `error_category`，不记原始消息（可能含凭据/路径，`nexusbridge/client.go:353-357`）。

### 构造器

| 场景 | 构造器 | 位置 |
|---|---|---|
| 纯业务错误 | `toolError(code, msg, category)` | `app/errors.go:7` |
| 需附结构化细节 | `toolErrorDetails(...)` | `:11` |
| 需保留底层 cause | `toolErrorCause(...)` | `:15` |

`Category` 决定 HTTP 状态码：`validation`→400、`not_found`→404、其它→500。**填错 category 会让客户端重试策略失效**。

### 解码

`internal/app/input_decode.go:13 typedToolHandler[T]` 是泛型包装：`json.Unmarshal` + `ensureJSONEOF`（拒绝尾随内容）。手写解码器必须同样拒绝尾随 —— 这是防走私的约定。

## 4. 日志

`slog` JSON handler（`cmd/agentdock/internal/logx/logx.go:8-24`）：

| 项 | 约定 |
|---|---|
| API | 只用 `slog.Info/Warn/Error` + 结构化 key-value |
| 级别 | 环境变量 `AGENTDOCK_LOG_LEVEL`，非法值静默落 `info` |
| 输出 | 由启动链决定：普通进程 stderr；桌面后台进程传入轮转文件 |
| 格式 | JSON，不自定义文本格式 |
| 禁止 | 打印凭据、token、完整 URL query（含 `sig`）、用户路径 |

**日志策略有测试兜底**：`scripts/test/logging_policy_test.go` 断言 compose 的 `max-size: 10m` / `max-file: 5` 各 3 处、OpenRC unit 必须走托管日志目录（`checkpath -d -m 0750`）、systemd 必须保留 journald（禁止 `StandardOutput=append:` 重复写文件）。

改 `internal/installer/units.go` 的日志部分是**高危改动** —— 会直接打破这三条断言。

## 5. 并发与生命周期

| 规则 | 依据 |
|---|---|
| 长任务不得持有 `lifecycleMu` | `Runtime.Close` 在 `:212-214` 明确注释：`BeginClose()`/`WaitForStarts()` 不持锁，否则死锁（陷阱 B1） |
| 短绑定后升级为版本读租约 | `plugin.Store.AcquireBinding` 注释：长期工作必须 `AcquireVersionRead` |
| 清理顺序固定 | `Close` 顺序 acp → browser → command → dynamicMCP → `ReleaseMCPLeases`；改顺序会留悬空进程 |
| 回滚用 `context.WithoutCancel` | `updateengine/arbiter.go:105` 的 3 分钟独立预算，父 ctx 取消不得中断回滚 |
| `panic` 只在进程边界收敛 | Nexus `invoke` 的 `recover()`（`client.go:288-303`）；stdio 路径无 recover（陷阱 A6） |

## 6. 脚本治理

`scripts/governance/inventory.yaml` 是脚本的**唯一注册表**，`TestScriptGovernanceInventoryCoversTrackedScripts`（`script_governance_test.go:14`）双向校验：

- 每个被 git 跟踪的 `*.sh`/`*.ps1`/`*.py`/`*.iss`（限 `scripts/`、`packaging/`、`docker-entrypoint.sh`）必须在清单里；
- 清单里的每一项必须真实存在且被跟踪；
- 超过 `review_threshold_lines: 300` 必须写 `oversize_justification` 或标 `legacy_oversize`；
- `class: legacy` 且超行数必须是 `legacy_oversize`。

### 分类语义

| class | 含义 | 约束 |
|---|---|---|
| `bootstrap` | 公开安装入口 | 不得改名删除（`public_contract: true`） |
| `runtime-adapter` | 平台外层适配（UAC/DPAPI/Registry/session） | 需 `public_contract` 声明 |
| `packaging` | 构建与打包 | — |
| `test` | 测试脚本 | 大多 `deletable: true` |
| `dev` | 本地开发辅助 | — |
| `legacy` | 历史遗留 | **禁止新增产品能力** |
| `ci` | CI 专用 | — |

**当前只有两个 `public_contract: true` 的公开入口**：`scripts/install/install.sh`、`scripts/install/install.ps1`。`docs/installer-script-inventory.md` 也把公开面限定为这两个。

新增脚本的流程：写文件 → 加清单条目 → `make test-scripts`。

## 7. 注释

| 场景 | 要求 |
|---|---|
| 导出的类型/函数 | 不强制 godoc；仓内多数导出符号无注释 |
| 非显然的取舍 | **必须**写"为什么"，不写"做什么" |
| 安全相关 | 必须显式声明边界，例：`workspace.Clean` 注释"不是安全边界" |
| 平台差异 | 在 `_windows.go` / `_darwin.go` 顶部说明差异来源 |
| 中文 vs 英文 | 二者混用；用户可见错误信息与安装器/桌面端注释用中文，核心库注释英文居多 |

最典型的注释价值示例（`plugin/store.go:455-457`）：

> protects only the brief state->version binding window. Long-running Plugin work must use AcquireVersionRead after resolving state.

一句话解释了一个否则会导致 GC 误删的陷阱。
