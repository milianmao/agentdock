# 核心功能模块

## 模块总览

AgentDock 对外暴露 31 个 MCP 工具，内部由 14 个能力包承载，全部通过 `internal/app/specs_registry.go:5 buildToolSpecs` 按固定顺序注册。

| # | 能力组 | 工具 | 可用性门 | 实现包 |
|---|---|---|---|---|
| 1 | 上下文 | `agentdock_context`、`workspace_context` | 始终 | `internal/app` |
| 2 | 文件 | `read_file`、`list_dir`、`search_text`、`file_edit` | 始终 | `internal/tool/file` |
| 3 | 命令 | `exec_command`、`session_observe`、`session_act` | 始终 | `internal/tool/command` |
| 4 | 任务 | `task_manage` | 始终 | `internal/tool/task` |
| 5 | 演进 | `evolve` | `NexusEndpoint != ""` | `internal/evolution` |
| 6 | ACP | `acp_session`、`acp_prompt`、`acp_interaction` | `ACPEnabled` | `internal/tool/acp` |
| 7 | 工作流 | `workflow_template_manage` | `NexusEndpoint != ""` | `internal/tool/task` |
| 8 | Skill | `skill_manage` | 始终 | `internal/tool/skill` |
| 9 | Plugin | `plugin_manage` | 始终 | `internal/tool/plugin` |
| 10 | 动态 MCP | `mcp_manage`、`mcp_tool_search`、`mcp_tool_inspect`、`mcp_tool_call` | 始终 | `internal/tool/mcp` |
| 11 | 图像 | `view_image` | 始终 | `internal/tool/media` |
| 12 | Recall | `recall_search`、`recall_read`、`recall_write`、`recall_maintain`、`private_note_manage` | `NexusEndpoint != ""` | `internal/tool/recall` |
| 13 | 浏览器 | `browser_session`、`browser_act`、`browser_snapshot` | `BrowserEnabled` | `internal/tool/browser` |
| 14 | 发布 | `file_publish` | 始终 | `internal/tool/media` |

可用性门定义在 `internal/app/specs.go:152-154`：`requiresNexus`、`requiresBrowser`、`requiresACP`。未通过的工具有两个效果：不出现在 `tools/list`，且不出现在 `agentdock_context` 的能力索引里。

工具动作枚举与入参 schema 的完整清单 → 详见 [服务层与IPC通信](../04-数据与组件设施/服务层与IPC通信.md#4-工具动作枚举)

## 逐模块职责

### 上下文组

| 工具 | 职责 | 关键约束 |
|---|---|---|
| `agentdock_context` | 一次性返回设备全貌：工作区、Skill 索引、Plugin 索引、动态 MCP、任务、Recall、Workflow、ACP | 输出 schema 来自共享 `mcpcontract.LocalAgentDockContextOutputSchema()` |
| `workspace_context` | 只返回工作区树与 `AGENTS.md` 类指令文件内容 | 用 `os.Root` + 文件身份校验，物理文件去重 |

`agentdock_context` 是模型进入设备的**唯一入口约定**：它把可用能力压缩成一份索引，避免模型盲试工具名。Plugin 描述在此处截断到 160 字符。

### 文件组

`read_file`（UTF-8 文本切片）、`list_dir`（深度/glob/类型过滤）、`search_text`（文本或正则，`doublestar` 匹配）、`file_edit`（`replace`/`patch`/`add`/`delete`/`move` 五动作）。

统一路径模型（`config.PathModel = "host"`）：相对路径从 `~/AgentDock` 解析，绝对与 `~/` 走 Host 规则。`file_edit` 的 `patch` 动作解析用 `filepath.Clean`，**明确不是安全边界**；真正边界在 `workspace.ResolveExisting`/`ResolveForWrite` 的 `EvalSymlinks`。

### 命令组

`exec_command` 支持 PTY 会话与后台会话；`session_observe` 只读列举/查看；`session_act` 写入或停止。输出上限 `MaxOutputBytes`（schema 常量导出）。

Skill 感知：`exec_command` 通过 `SkillResolver` 拿到 `SkillLease`，把 `SKILL_DATA_DIR` 与该 Skill 的环境变量注入子进程。`managed` 与 `plugin` 两种来源分别映射到不同数据目录与 env scope（`internal/app/runtime.go`）。

### 任务组

`task_manage` 的 8 个动作：`create`/`list`/`get`/`checkpoint`/`block`/`resume`/`final_review`/`complete`。状态机、上限、事件结构 → 详见 [Store状态管理全景](../04-数据与组件设施/Store状态管理全景.md#1-taskstatestore)。

`workflow_template_manage` 的 7 个动作：`publish`/`retire`/`get`/`get_many`/`list`/`match`/`vector_index`，模板存储在 NexusDock，本地只读缓存活跃版本。

### 演进组

`evolve` 是 AgentDock 的**自演化引擎**，唯一权威实现；NexusDock 只存 Recall 与 Workflow，不做演进。`intent` 枚举四个值：`propose`、`bind`、`supersede`、`retract`（`internal/evolution/contract.go:10`）。任务通过 `EvolutionBindings` 与演进记录关联，`checkpoint` 前会做绑定校验（`evolution.ValidateBindings`）。

### ACP 组

每个 profile 一个 `acpruntime.Manager`。`acp_session` 8 动作管理会话生命周期；`acp_prompt` 启动异步 Run、读有序事件、取消；`acp_interaction` 处理权限与 elicitation 请求。

steering（运行中改指令）是内部实现细节，不暴露为独立 action。

### Skill / Plugin 组

`skill_manage`：`install`/`remove`/`env_set`/`env_unset`/`env_list`。单目录 swap + journal，**无版本概念，只有内容摘要**。

`plugin_manage`：`inspect`/`validate`/`install`/`update`/`enable`/`disable`/`remove`。多版本、activation journal、三级文件租约、Plugin 内可含多个 Skill 与多个 MCP 组件。

两条链路的事务差异 → 详见 [Skill安装与替换全链路](../03-核心数据业务流/Skill安装与替换全链路.md)、[Plugin审核安装激活全链路](../03-核心数据业务流/Plugin审核安装激活全链路.md)

### 动态 MCP 组

远端 MCP server 的工具**不注册进** AgentDock 的 `tools/list`，由 4 个固定代理工具承载：`mcp_manage`（9 动作，含 OAuth 授权）、`mcp_tool_search`、`mcp_tool_inspect`、`mcp_tool_call`。

`mcp_tool_call` 是双层校验：外层 schema 只要求 `{name, arguments}` 且 `arguments` 开放；内层用远端 `inputSchema` 重新编译 validator 校验真实参数。

### 媒体组

`view_image` 支持 `artifact_id` / Host 路径 / HTTP(S) URL；`file_publish` 把本地文件或目录（目录打 tar.gz）发布为不可变 artifact，返回 `artifact_id` 与临时签名 URL。

### Recall 组

5 个工具，全部依赖 Nexus 配对（`private_note_manage` 的描述标注低频、默认不用）。`recall_write` 要求模型显式选择 `target=card|markdown` 与 `action`，不允许猜测。`private_note_manage` 搜索只回元数据，明文仅在显式 read 时返回，Git 备份只含 age 密文。

### 浏览器组

`browser_session` 启动或附着 CDP 浏览器；`browser_act` 执行严格校验的 CSS/CDP 动作并回最终快照 + 截图；`browser_snapshot` 只读采集。

动作枚举含 `goto`/`click`/`fill`/`press`/`wait`/`wait_for_selector`/`wait_for_url`/`wait_for_text`/`wait_for_response`/`select`/`scroll`/`reload`/`back`/`forward` 加键盘键。

## 非工具模块

### CLI 子命令（`cmd/agentdock`）

| 子命令 | 职责 |
|---|---|
| `version [--json]` | 版本与构建信息 |
| `update` | 自更新（`--check` / `--progress-json` / `--local-archive`） |
| `service` | 托管服务生命周期（macOS launchd / Windows 服务 / Linux systemd） |
| `tunnel` | cloudflared 隧道（quick/named、regenerate、configure） |
| `component` | cloudflared 托管组件（catalog/install/update/uninstall） |
| `config` | 配置读写 |
| `skill bootstrap` | 首次安装内置 Skill bundle |
| `nexus pair\|status` | 设备配对 |
| `install` / `uninstall` | 事务式安装卸载 |

### 桌面端

| 平台 | 文件数 | 职责 |
|---|---|---|
| macOS（Swift/AppKit） | 34 | 托盘、原生控制面板、更新进度窗、服务控制、权限检查、隧道令牌 |
| Windows（C#/WinUI 3） | 5 页 + tray | 首页/连接/能力/设置/活动、托盘、DPAPI、命名管道 IPC |

桌面端不持有业务状态，只读 Runtime API 与 `DispatchControlRequest`。

### 内置 Skill（`core-skills/`）

| Skill | 触发场景 |
|---|---|
| `agentdock-user-guide` | 用户问 AgentDock 是什么、怎么配、不同平台怎么改配置、如何接 ACP |
| `plugin-import` | 从 Git/GitHub/marketplace 取 Plugin 到本地再交给 `plugin_manage` |
| `skill-authoring` | 创建/修改/验证 Skill 本身 |
| `skill-installation` | 审查、安装、配置、更新、移除 Skill |

4 个 Skill 随镜像/安装包分发到 `/usr/local/share/agentdock/core-skills`，首启用 `skill bootstrap --bundle` 装入。
