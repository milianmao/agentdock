## ⚠️ 契约 wiring 验证提醒

本评审验证了**三份文档之间**的一致性（字段定义、错误码、工具名、验收标准），以及**Go 实现与契约的字段级对齐**（`contract.go` schema ↔ `service.go` 实际输出）。

以下契约项在 Go 侧由**五道机械门禁**兜底，不依赖人工 grep：

1. **契约中定义的每个工具名** → `TestOutputContractCoverageMatchesPublicTools`（`internal/app/output_contract_coverage_test.go:56`）用 `outputContractCoverageFindings` 比对运行时 `ToolDefinitions()` 与 `outputContractCoverageInventory`（`:51-52` 登记 `computer_status`/`computer_call`），少一条或多一条都 FAIL；`TestOutputContractCoverageGuardDetectsMissingAndInvalidEntries`（`:62`）反向自测该 guard 本身有效。
2. **启用时输入 schema 必须非空且能编译** → `NewRuntime` 调 `compileAvailableToolContracts`（`runtime.go:70`）→ 对每个 available spec 断言 `InputSchema`/`OutputSchema` 非空（`specs.go:136-141`）并 `CompileInputSchema`（`:142`）。`TestComputerToolsAreFeatureGated` 在 `CodexHostEnabled=true` 下真实走 `NewRuntime`（`computer_tools_test.go:38`），因此这条断言对 computer 两工具**实际生效**。另有 `TestRuntimeToolsHaveRegistryDefinitionsAndSchemas`（`internal/mcp/registry_test.go:26`）+ `assertObjectSchema`（`:244-255`）校验 object 形状，但其 `config.Config` 未开 `CodexHostEnabled`（`:27-31`），computer 两工具不在其遍历范围内。
3. **输出 schema 顶层字段禁令** → `TestToolOutputSchemasDoNotExposeGenericOK`（`internal/mcp/registry_test.go:52`）对全 registry 断言：顶层 `properties` 不含 `ok`（`:56-58`），且 `required` 列表不含 `ok`（`:59-64`）。
4. **特性门控** → `TestComputerToolsAreFeatureGated`（`internal/app/computer_tools_test.go:12`）双向断言：false 时 0 个、true 时恰 2 个 computer 工具。
5. **契约端点覆盖率** → `contract-oracle-extractor` 自证 `ratio ≥ 0.80`（实测 1.0）。

补充说明：`TestCanonicalToolDefinitionsMatchSharedContract`（`internal/app/mcp_contract_test.go:10`）只覆盖 `mcpcontract.IsCanonicalTool` 为真的工具（`:13`），computer 两工具**不在**其中——它们的 schema 事实源是本地 `internal/tool/computer/contract.go`，因此不能靠这条测试兜底。

**上述门禁均为 CI 必过项；任一条 FAIL 不得合并。**

未覆盖的 wiring：契约 §1 的 12 个 `CODEXHOST_*` 与 4 个 `COMPUTER_*` 错误码**没有**「码表 ↔ 常量」的机械比对测试。当前靠人工核对（`errors.go:11-24` / `internal/tool/computer/errors.go:14-19`），建议后续补一个反射遍历常量前缀的用例。
